# Task 5: 防災ヒントセクション作成

> 仕様: [../result-page-spec.md](../result-page-spec.md) セクション 5

## ステータス: ✅ 実装完了（仕様確認済み）

## 対象ファイル

- `client/src/pages/ResultPage.jsx`

## 概要

ゲーム中のプレイヤーの選択に基づいて、現実の防災に活かせるヒントを動的に表示するセクション。
「あれば～かもしれない」という反事実的な視点で学習を促進。

## 実装内容

### ヒント生成ロジック

5つの条件に基づいてヒントを動的に生成：

| 条件 | ヒントテキスト |
|------|----------------|
| コンビニ未訪問 | 「現金があれば、キャッシュレス決済が使えなくなっても皮てすぐに済んだかもしれない。」 |
| モバイルバッテリー未訪問 | 「モバイルバッテリーを持ち歩いていれば、電源を心配する場面を減らせたかもしれない。」 |
| 最終所持金が 0 | 「小銭を常に持ち歩いていれば、緊急時の行動選択肢が広がったかもしれない。」 |
| 最終充電が 0 | 「スマートフォンの充電を日ごろから心がけていれば、情報収集が途絶えなかったかもしれない。」 |
| 最終精神力が 30 未満 | 「複数の避難場所を事前に把握していれば、精神的な余裕が生まれたかもしれない。」 |

### UI実装

- カード形式（ヘッダー + ボディ）
- ヘッダー: 「防災に向けて～生存のヒント～」
- ボディ: 複数のヒント（赤太字, `text-maintext`, `color: var(--color-theme10)`）
- gap: 1vh でヒント同士を区切り
- 0件の場合は「防災へのヒントがこのプレイには含まれていません」と表示（フォールバック）

### 配置

ResultPage の生死を分けた選択（セクション4）の直後、想定地震情報（現セクション5 → 新セクション6）の前に配置。

## データフロー

```
visitedFacilitiesAtom
  ↓
fac_003, fac_001 を確認 → コンビニ、モバイルバッテリー訪問の有無判定

moneyAtom, chargeAtom, mentalAtom
  ↓
終了時のゲージ値を確認 → 0 かどうか、30未満かどうかを判定

↓
条件マッピング → ヒント配列生成
  ↓
ResultPage で map() でレンダリング
```

## レビューポイント

- 5つの条件が正しく判定されているか
- ヒントテキストが正確に表示されているか
- 0件の場合のフォールバック表示
- カードスタイルが他セクションと統一されているか
- ヒント間のgap（1vh）が正しく適用されているか
